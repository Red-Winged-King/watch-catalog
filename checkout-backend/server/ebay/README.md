# eBay adapter notes

`EbayClient` is a server-only Production adapter. Construction does no I/O. Its OAuth credentials come only from `EBAY_CLIENT_ID`, `EBAY_CLIENT_SECRET`, `EBAY_RUNAME`, an optional `EBAY_CALLBACK_URL` custom-domain override, and a base64-encoded 32-byte `TOKEN_ENCRYPTION_KEY`; neither access nor refresh tokens are logged or returned from module methods.

The seller consent URL requests `sell.inventory`, `sell.account.readonly`, `sell.fulfillment.readonly`, `commerce.identity.readonly`, and eBay's base OAuth scope for the read-only Trading XML calls. Code exchange posts form data to `POST https://api.ebay.com/identity/v1/oauth2/token` using the documented Basic client authentication. eBay's documented code-grant token response has no `scope` member, so the encrypted connection persists the exact requested consent set when that optional member is absent; if it is present, all required scopes must be included. The client calls `GET https://apiz.ebay.com/commerce/identity/v1/user/` with the User token before encrypting the refresh token as `v1.iv.tag.ciphertext` using AES-256-GCM. The short-lived access-token cache is in memory and keyed to the stored seller ID.

The Inventory calls use these documented paths: `PUT /sell/inventory/v1/inventory_item/{sku}`, `POST /sell/inventory/v1/offer`, `GET /sell/inventory/v1/offer/{offerId}`, `POST /sell/inventory/v1/offer/{offerId}/publish`, `POST /sell/inventory/v1/offer/{offerId}/withdraw`, and `POST /sell/inventory/v1/offer/get_listing_fees`. Fee estimation sends `{ offers: [{ offerId }] }` and accepts only one complete EBAY_US fee summary with parseable USD amounts. It fails closed for warnings, missing fee detail, unsupported currency, or ambiguous totals. Publication and withdrawal are sent once with no automatic retry.

Seller setup uses the caller's seller User token to read `GET /sell/inventory/v1/location/{merchantLocationKey}` and Account API `GET /sell/account/v1/{fulfillment_policy|payment_policy|return_policy}?marketplace_id=EBAY_US`. It requires the configured returned policy IDs, an enabled location whose country exactly matches the configured `shippingOriginCountry`, US-only delivery metadata, no global/international shipping, flat-rate verifiably zero buyer shipping, and immediate payment. Missing or ambiguous metadata is not treated as approval.

Sale evidence calls only read endpoints: Trading XML `GetItem` for exact listing ID, SKU, `SellingStatus.QuantitySold`, and `ListingStatus`; fully paginated Trading `GetItemTransactions`; and fully paginated Fulfillment `GET /sell/fulfillment/v1/order` filtered from the listing lifetime. A matching fulfillment line item must have both the exact `legacyItemId` and SKU. Any matching transaction/order commits the listing regardless of payment status, including `PENDING` and `FAILED`. It rejects DTD/entity XML before `fast-xml-parser` parsing and fails closed for malformed responses, unexpected enums, missing fields, inconsistent IDs/SKUs, pagination inconsistencies, or request failures. It has no cancellation, refund, purchase, or order mutation route.

## Official endpoint and scope sources

- [eBay authorization-code grant and refresh-token guide](https://developer.ebay.com/develop/guides/sell/authorization) documents the consent URL parameters, RuName redirect URI, token endpoint, Basic credentials, and refresh request body.
- [eBay Identity API OpenAPI](https://developer.ebay.com/develop/api/spec/identity_api.json) documents `GET /commerce/identity/v1/user/`, the User-token requirement, and `commerce.identity.readonly`.
- [eBay Inventory API OpenAPI](https://developer.ebay.com/develop/api/spec/inventory_api.json) documents the Inventory paths, `getListingFees` `{ offers: [{ offerId }] }` payload, fee summaries, offer status, and listing ID response fields.
- [eBay Account API OpenAPI](https://developer.ebay.com/develop/api/spec/account_api_v1.json) documents fulfillment, payment, and return policy IDs, marketplace IDs, `immediatePay`, shipping services, and region metadata.
- [eBay Fulfillment API OpenAPI](https://developer.ebay.com/develop/api/spec/fulfillment_api.json) documents `getOrders` creation-date filtering, `limit`/`offset` pagination, `orderPaymentStatus`, `legacyItemId`, SKU, and line-item quantity.
- [eBay GetItemTransactions reference](https://developer.ebay.com/devzone/xml/docs/reference/ebay/getitemtransactions.html) documents XML pagination, `HasMoreTransactions`, `Item.SellingStatus.QuantitySold`, and `Transaction.QuantityPurchased`.
- [eBay OAuth with Traditional APIs](https://developer.ebay.com/api-docs/static/oauth-trad-apis.html) documents use of OAuth User tokens for Traditional APIs and the requirement to request all scopes needed by the called methods.

The verified default OAuth Accepted URL is https://watchbuy-ko4chrlv.manus.space/api/ebay/callback. The owner dashboard can copy a fresh 32-byte base64 encryption key directly from browser cryptographic randomness to the clipboard for protected initial input. The key is never rendered, logged or transmitted to an application API, and that control is hidden once a key is configured.
